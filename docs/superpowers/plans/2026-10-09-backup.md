# Backup and restore by file (Phase 15) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Task 2 also applies `ui-ux-pro-max`.

**Goal:** export all data to a `.lunamom` file (versioned JSON) and restore it by replacing everything, atomically. The restore can start from Profile, from onboarding, or by opening the file from another app.

**Spec:** `docs/superpowers/specs/2026-10-09-backup-design.md` (binding).

## Global Constraints

- **Branch.** Work on `feat/backup` in `/Users/macos/Documents/kick-counter`, which is already checked out. Never change the `gh` account.
- **Forbidden edits:** workflows, `scripts/ci.sh`, `scripts/test-core.sh` and entitlements.
- **Allowed `project.yml` edits** (approved): the Info properties `CFBundleDocumentTypes`, `UTExportedTypeDeclarations` and `LSSupportsOpeningDocumentsInPlace` for the `.lunamom` type.
- **KickCore imports.** `KickCore` must not import SwiftUI, UIKit, SwiftData or CloudKit. KickCore holds the format, the codec, the validation and the summary. KickData holds the store-level export and replace.
- **Strings.** Only through `scripts/add-strings.py`, en + vi, northern Vietnamese.
- **Tokens.** Luna colour tokens with contrast pairs that `LunaContrast.usages` already lists. Fonts only through `Font.luna`.
- **Local verification.**
  - Run `scripts/test-core.sh`, then `swift test` in `Packages/KickData`.
  - Run `xcodegen generate --quiet` and `xcodebuild … -derivedDataPath build/DerivedData CODE_SIGNING_ALLOWED=NO -quiet build-for-testing` on 'iPhone 18 Pro'.
  - Never run the full UI suite locally. A single new UI test may be run locally only if CI debugging needs it.
- **Commits.** The trailer is `CI-Only-Testing: A,B` (comma-separated) followed by `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. After each commit: push, then `scripts/ci-wait.sh`. Do not push while a run for this branch is in progress.
- **Safety.** Restore must never leave a half-replaced store. Prove this with a test that injects a save failure. Decode errors never touch any data.

## Task 1: KickCore + KickData

**KickCore:**
- `Backup.swift`: `BackupDocument` and the DTOs (`SessionDTO` with kicks, `AppointmentDTO`, `PeriodDTO`, `CycleLogDTO` including the unknown raw lists, `WeightDTO`), plus their conversion to and from the records.
- `BackupSettings`: an explicit table of key → type (`bool`, `int`, `double`, `string`, `date`). It is derived from `AppDataReset.ownedKeys` minus the partner keys and `hasCompletedOnboarding`, and includes the new `SettingsKey.lastBackupAt` (add it to `SettingsKey` and to `ownedKeys`). It provides `read(from: UserDefaults) -> [String: BackupValue]` and `write(_:to:)`.
- `BackupCodec`: `encode`/`decode` plus the error enum (spec §3).
- `BackupDocument.summary`: the counts, `createdAt`, the mode and the date range.
- `BackupValidation.clean(_ doc:, now:, calendar:) -> (BackupDocument, skipped: Int)`.

**Tests:** spec §6, the KickCore part. Add a test that `BackupSettings` covers `ownedKeys` minus the exclusions exactly, so a future key cannot be forgotten.

**KickData:** `BackupStore` with:
- `export(container) -> (sessions, appointments, periods, logs, weights)` as records;
- `replaceAll(container, with:)`, which deletes all models and inserts the new records in one context, saves, and rolls back on throw.

Test it with an in-memory container, including an injected failure. Look at how `DataReset` injects or simulates a failure and reuse that.

**Commit trailer:** `CI-Only-Testing: AppStoreReadinessUITests`.

## Task 2: App

- **Profile.** Add a "Dữ liệu" section with:
  - export (`profileBackupExport`), using `ShareLink` with a file URL, or `UIActivityViewController` if `ShareLink` cannot show the share sheet reliably;
  - restore (`profileBackupImport`), using `.fileImporter` with `UTType("com.lmtiep.kickcounter.backup")` and `.json`;
  - the footnote and the last-backup line.
- **Document type.**
  - In `project.yml`, declare an exported UTType for extension `lunamom`, conforming to `public.json` and `public.data`, and a document type with role Viewer, rank Owner.
  - In `RootView`, `.onOpenURL` with a file URL ending in `.lunamom` reads it (security-scoped access if needed), decodes it and presents `RestoreBackupSheet`. This works during onboarding too: present it above the onboarding cover.
- **`RestoreBackupSheet`** follows spec §4.2: the summary, the warning, the running-session note, the errors, the atomic restore, the reload, the toast and the Today tab.
- **Onboarding.** Add a "Khôi phục từ bản sao lưu" link on the welcome step (`onboardingRestore`), which opens the file importer.
- **Delete-all** also clears `lastBackupAt`, which is automatic through `ownedKeys`.
- **Strings:** all new keys in vi + en.
- **DEBUG test hook.** `-uiTestingRestoreFile <path>` opens the restore flow for that file. Add a fixture `UITests/Fixtures/sample.lunamom` that the test copies into the app's tmp folder: write it from the test bundle, or embed the JSON in the test and pass a temporary path through the launch environment. Also create the fixture from KickCore's encoder in a unit test, so the format stays in sync.
- **UI tests** (spec §6): `BackupUITests` and `BackupScreenshotTests`.

**Commit trailer:** `CI-Only-Testing: BackupUITests,BackupScreenshotTests,ProfileUITests,OnboardingUITests,AppStoreReadinessUITests`.
